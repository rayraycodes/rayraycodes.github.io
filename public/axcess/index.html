Local-first accessibility expert workbench

From site scan to evidence you can defend.

Axcess renders public or authorized login-protected pages in a real browser, shows exactly what is being tested, groups the evidence into actionable issues, and exports a structured Excel workbook for expert review.

One focused flow

Scan → progress → issues → Excel workbook

The interface is organized around the work an accessibility professional is doing, not around internal crawler terminology.

  1. Choose the scope

    Enter a seed URL, set a page limit, choose axe-core, Alfa, or both, and decide whether optional OCR or local-model analysis belongs in this evaluation.

  2. Watch the crawl

    See the current page, discovered and completed totals, which method is running, and an ETA range without the view refreshing or stealing scroll position.

  3. Understand the evidence

    Read one table showing what the issue is, why it matters, the expected fix, and the exact page, element, selector, or image where it was detected.

  4. Deliver and verify

    Export a linked Excel workbook that summarizes scope, limitations, priorities, evidence, remediation, and verification steps, then rescan to compare new, resolved, and still-open barriers.

No hidden pass: “Selected” means a method was requested. Axcess separately reports whether it actually ran, how many pages it checked, and why it was skipped or unavailable.

  3. Download axcess-windows-x64 or axcess-macos-apple-silicon, extract the ZIP, and open the installer or application archive.

Actions artifacts are temporary; this page automatically follows the newest successful build when an older artifact expires.

macOS: open the unsigned preview
  1. Download and extract the macOS artifact until Axcess.app is visible.
  2. Double-click Axcess.app. If macOS blocks it, click Done.
  3. Choose Apple menu → System Settings → Privacy & Security.
  4. Scroll to Security, find the message that Axcess was blocked, and click Open Anyway. This option is available for about one hour after the blocked launch.
  5. Authenticate with your Mac password or Touch ID.
  6. Click Open in the final confirmation dialog.
  7. Keep the Axcess Desktop window open while using it. Closing the window stops its private local service.

The app binds to loopback only, chooses an available port, and stops its backend when the desktop window closes.

Local evidence storage

Reports, the SQLite database, screenshots, and blobs stay under the operating system’s Axcess application-data directory.

Public and authenticated scope

The same evaluation choices for both scan modes

A login page changes how the browser session is established; it should not hide the engine, page-limit, OCR, or local-AI controls that define the evaluation.

Public website

Start immediately

Axcess follows the approved URL scope and tests the rendered experience. Browser mode handles JavaScript applications and sites that block plain HTTP crawlers.

Login or 2FA website

You sign in; Axcess scans after

A visible browser opens for an authorized auditor to complete password, passkey, SSO, or 2FA directly with the site. Credentials and second factors are not requested by Axcess.

  • Confirm the approved post-login page before scanning.
  • Use a least-privilege test account and owner-approved scope.
  • Authentication accessibility still requires a manual check.

Complementary evidence

What checks what

No single engine can evaluate accessibility. Axcess keeps every result tied to its source layer so an expert can judge its confidence and limitations.

01

Browser rendering

Loads client-side JavaScript and creates the page state the other browser-based methods inspect. Rendering alone is not a pass.

Source layer: browser

02

axe-core

Runs deterministic rules against the rendered DOM for automatically testable accessibility conditions.

Source layer: axe

03

Siteimprove Alfa

Runs an independent set of ACT rules. ACT means Accessibility Conformance Testing: each rule defines a precise condition and can return passed, failed, or cannot tell.

Source layer: Alfa / ACT

04

Keyboard and focus probes

Walk focus forward and backward, attempt Escape behavior, inspect frames, and record conservative review leads for traps or obscured focus.

Source layer: browser behavior

05

Responsive and zoom probes

Check 320 CSS-pixel reflow, enlarged text, and text-spacing overrides for clipping, lost content, and two-dimensional scrolling.

Source layer: browser behavior

06

Image-of-text analysis

Tesseract OCR finds visible text candidates; an optional local vision model classifies whether the text is meaningful and needs expert attention.

Source layer: OCR + local vision model

07

Semantic review

An optional local language model evaluates contextual questions such as link purpose. Its output is a review lead, never a conformance verdict.

Source layer: local language model

08

Visual and motion probes

Combine live-page screenshots, DOM evidence, and runtime media behavior to flag reading-order or uncontrolled-motion questions.

Source layer: visual + browser behavior

Designed for accessibility professionals

Automation proposes evidence. The expert decides.

Axcess was shaped around an accessibility specialist’s reporting workflow: reduce duplicated evidence, make false-positive decisions auditable, and keep uncertainty visible to the stakeholder receiving the report.

Lower-noise behavioral leads

The keyboard-trap probe requires repeated, bidirectional evidence and suppresses ordinary focus wrapping, small cycles, modal containment, and opaque focus contexts. A lead still requires manual confirmation.

Draft and final mean different things

A draft can preserve unresolved evidence. A final handoff requires explicit expert disposition of actionable groups, while confirmed open barriers remain visible in the remediation worklist.

Local model use is optional

Browser rules and probes work without a model. OCR and Ollama-powered review can be skipped; method coverage clearly states what did and did not run.

Desktop and web workflows

The web application remains the expert workbench. Verified Windows x64 and Apple silicon Electron builds package that interface with its private local service and required scan runtimes.

Important limitation: Axcess supports an evaluation; it does not certify legal compliance or prove whole-site WCAG conformance. Manual testing with assistive technologies and experienced judgment remains necessary.
